SLIDE 02 / 12

What can a harness change?

Harness 的八種元件

口說講稿 完整版

我們平常在用 agent 的時候，除了選 model，還要決定給它什麼 instruction、能用哪些工具、什麼時候載入 skill，以及怎麼檢查最後的結果。這些 model 外面的設定和執行機制，paper 統稱為 harness。

那具體可以改哪些東西？這張圖把 harness 拆成八種 component，再按照它們在 agent 執行時的作用，分成四個區塊。

先看左邊的 context construction，也就是決定 model 會讀到哪些資訊，以及什麼時候讀到。System prompt 決定基本的角色和做事方式，guardrails 放需要遵守的規則，
memory 則保存執行時會用到的長期資訊。這三種內容會在每次 model call 時提供。Skill 的用法不太一樣。它可以放某一類工作的完整操作步驟，等到 agent 需要做這類工作時，再載入這些內容，
就不用一開始把所有操作說明都放進 context。

再看右邊的 tool interface，也就是 agent 使用工具的部分。Tool guidance 告訴 agent 什麼時候、怎麼使用現有工具。Script 則是可以直接執行的程式，比如讀資料、轉檔，或檢查輸出。

下面的 orchestration 處理的是工作怎麼分配。這裡的 subagent 可以接手一部分工作，在自己的 context 裡處理，再把結果傳回主要的 agent。最後看 middleware，也就是 plugin 所在的區塊。Plugin 會在工具呼叫前後等時間點執行預先寫好的程式，例如檢查工具結果。到了設定的時間點，這些檢查就會執行，不需要等 model 自己決定要不要做。

這些 component 實際上都存成檔案。修改 harness 時，就會去編輯對應的 instruction、操作步驟或程式，再用修改後的設定執行 task。有了可以修改的地方，接下來要分清楚的是，誰在執行 task，誰在看執行結果並修改這些檔案。

我們使用 agent 時，除了選 model，還要設定 instruction、工具、skill，以及結果怎麼檢查。Paper 把這些設定和執行機制叫做 harness。

這張圖有八種 component。System prompt 決定基本角色和做事方式，guardrails 放規則，memory 保存執行時要用的資訊。這三種內容會在每次 model call 時提供；skill 則放特定工作的步驟，需要時才載入。

Tool guidance 說明工具怎麼用，script 是可以直接執行的程式。Subagent 可以接手部分工作，在自己的 context 裡處理。

Plugin 則在工具呼叫前後等時間點執行程式，不需要等 model 決定要不要做。

這些 component 都存成檔案，修改 harness 就是編輯這些檔案。接下來分清楚，誰執行 task，誰負責修改。

Two levels of recursion

兩層 recursion

口說講稿 完整版

在這個流程裡，我們先分清楚 executor 和 editor 這兩個角色。Executor 負責實際完成 task。它做事時使用的 execution harness，就是剛才介紹的八種 component。Editor 則負責讀取執行紀錄，找出工作方式可以改善的地方。

先看現在這一題。Editor 會提出修改，讓 executor 用修改後的 harness 重做同一個 task，再根據結果決定怎麼繼續改。這是第一層，paper 叫做 task-level recursion。

但 editor 自己也需要指引，知道應該看哪些問題、以前試過哪些做法。Paper 把支持這個修改過程的設定和經驗叫做 improvement harness，
其中會累積經驗的地方就是 library。這個 library 是給 editor 修改 harness 時參考的，和上一張圖裡 executor 執行時讀的 memory，用途不同。

在同一題裡，這份 improvement harness 先固定。等 task 做完，才回頭整理這次哪些修改有用、在什麼情況下有用，再更新 library。這是第二層，harnessing-level recursion。

下一題進來，execution harness 會從共同的初始版本重新開始。Editor 再去 library 找適合的 component 和經驗，調整成這一題需要的版本。最開始 library 是空的，第一題就先從自己的執行紀錄找問題。那我們先看當前這一題：沒有標準答案可以直接拿來評分時，editor 要怎麼判斷一個修改值不值得保留？

Executor 負責完成 task，使用的是 execution harness。Editor 則看執行紀錄，提出修改，讓 executor 重做同一題，再根據結果繼續調整。這是第一層，task-level recursion。

Editor 自己也需要指引。Paper 把支持修改過程的設定和經驗叫做 improvement harness，
其中累積經驗的地方就是 library。它是給 editor 修改時參考的，和 executor 執行時讀的 memory，用途不同。

同一題裡，improvement harness 保持固定。等 task 完成，才整理修改經驗、更新 library。這是第二層，harnessing-level recursion。

下一題仍從共同的初始 execution harness 開始，再參考 library 調整。最開始 library 是空的，第一題先從自己的執行紀錄找問題。

SLIDE 04 / 12

Propose, probe, compose

提出、測試、整合

口說講稿 完整版

Paper 的做法是，先觀察原本的 agent 怎麼做，再實際執行修改後的版本，對照行為有沒有改變。這個過程分成 Propose、Probe 和 Compose。

我們從圖的左邊開始看。先用原本的 harness 做一次 task，把執行過程和最後產出的東西留下來。執行過程叫做 trajectory，裡面會記錄 agent 做了哪些操作、呼叫了哪些工具。最後交出的程式、文件或其他成果，則叫做 deliverable。這兩個就是後面比較的參考。

接著是 Propose，也就是提出修改。一個 task 沒做好，可能是工作流程有問題，也可能是這個領域需要的做法沒有掌握好，所以 paper 分成兩個角度來看。Invariant editor 看的是規劃、工具使用，或 agent 有沒有太早結束工作。Domain editor 則看這類工作本身的要求，例如試算表的計算方式，或法律文件需要具備的結構。兩邊各自提出一個改好的 harness，這就是兩個 candidate。

到了 Probe，就讓這兩個 candidate 真的去做同一個 task。Executor 和環境設定保持一致，再比較修改前後的執行過程和產出。比如原本沒有重新打開輸出檔案，修改後有沒有真的去打開、檢查。這種前後對照就是 behavioral contrast，它讓 editor 有具體的行為證據可以判斷。不過，一次執行看起來比較好，還不能保證最後成果完全正確。

最後是 Compose。負責這一步的 composer，會一起看原本的執行、兩個 candidate 改了什麼，
以及 probe 的結果，再決定哪些修改值得整合、哪些需要調整。它也可以採用其中一個版本，或保留原本的 harness。組成新的 harness 之後，還會再執行一次 task，取得這個版本的成果。

這整套流程算一次 improvement step。後面講 k 等於 1，指的就是做一次這樣的流程。接下來看一個實際案例，看看執行紀錄裡的問題，怎麼變成具體的修改。

這個過程分成 Propose、Probe 和 Compose。

先用原本的 harness 執行 task，留下 trajectory，也就是操作和工具呼叫的紀錄，
以及 deliverable，也就是最後交出的程式、文件或其他成果。

Propose 是提出修改。Invariant editor 看規劃、工具使用等流程問題，domain editor 看這類工作的知識和程序要求。兩邊各提出一個改好的 harness，形成兩個 candidate。

Probe 讓兩個 candidate 在相同 model 和環境設定下，重做同一個 task。比如原本交出檔案後沒有檢查，修改後有沒有真的重新打開檔案？這種 behavioral contrast 提供修改前後的行為證據，但不能保證成果完全正確。

Compose 再根據修改內容和執行結果，整合有幫助的部分，也可以採用其中一個版本，或保留原本的 harness。組成的新版本還會再執行一次。

這整套算一次 improvement step，也就是 k 等於 1。接下來看實際案例。

SLIDE 06 / 12

Parallel width or sequential depth

Parallel 與 sequential

口說講稿 完整版

Paper 測試了兩種做法。左邊叫做 parallel，是從同一個起點多試幾種修改方案。右邊叫做 sequential，則是先改一輪，再根據這一輪的結果繼續改。這裡用 k 來設定探索量。對 parallel 來說，k 增加的是同一輪要嘗試的方案數量。對 sequential 來說，k 增加的是前後要做幾輪修改。

兩種做法一開始，都會先用原本的 harness 執行 k 次，了解它在這一題的表現，作為後面比較的參考。

先看 parallel。Invariant editor 和 domain editor 會各提出 k 個 candidate，
所以總共有 2k 個候選版本，每個都實際執行一次。接著開 k 個 composition session，每個 composer 都能看到全部 candidate 的修改和執行結果，
再各自組出一個新的 harness，拿去執行。例如 k 等於 5，就是兩種角度各提出五個 candidate，合計十個，再由五個 composer 根據這些結果，產生五個整合後的版本。

Sequential 則是一輪接著一輪。第一輪修改並執行之後，第二輪就用改好的 harness 作為起點，參考前面留下的紀錄，繼續提出修改、測試和整合。k 等於 5，就是連續做五輪，後面可以保留前面有效的做法，也可以修正前一輪造成的問題。

當 k 大於 1，最後會有幾份已經做好的成果，這時由 selector 對照 task 要求和原始資料，
從匿名的 deliverables 裡選出一份。前面的 composer 負責修改 harness，這裡的 selector 則負責選最後交出去的成果。它直接選現有的一份，不會再把幾份答案合寫成新的內容。k 等於 1 時，就直接交出基本流程的結果，跳過這個 selection。

k 是事先設定的，每次執行也有 turn 和時間上限。當這一題的成果交出去之後，接下來才整理這次修改留下的經驗。

Paper 測試兩種方式。Parallel 從同一起點多試幾種修改；sequential 則改完一輪，再接著改下一輪。k 用來設定探索量。

兩種方式都先用原本的 harness 執行 k 次，取得參考紀錄。

Parallel 讓兩種 editor 各提出 k 個 candidate，每個都執行。接著由 k 個 composer 參考全部結果，各自整合並執行新的 harness。k 等於 5，就是十個 candidate、五個整合後的版本。

Sequential 則把每輪改好的 harness 當作下一輪的起點，也保留前面的執行證據。k 等於 5，就是連續做五輪。

k 大於 1 時，最後由 selector 對照 task 要求和原始資料，從匿名的成果裡選一份。Composer 改的是 harness，selector 選的是已經完成的成果。k 等於 1 時，跳過 selection。

k 事先設定，每次執行也有 turn 和時間上限。Task 完成後，再整理修改經驗。

SLIDE 12 / 12

What does Harness² establish?

回到核心貢獻

口說講稿 完整版

最後，這篇的做法可以從三個動作來理解。

第一個是 Adapt。遇到目前的 task，先觀察原本怎麼執行，再提出修改、實際測試，整合成新的 harness。

第二個是 Remember。Task 做完之後，把可以重用的 component 和修改經驗留下來，說清楚什麼情況適用，以及哪些執行證據支持這個做法。

第三個是 Reuse。之後遇到新 task，editor 就可以參考這些經驗，挑選適合的 component，調整成這一題需要的版本。

實驗裡，一次 improvement step 就能改善三個 benchmark、四種配置的 base 表現。增加探索還能繼續提升分數，而拿掉 library、editor 分工或 composition，表現都會下降。Library 的實驗也顯示，之後即使沒有新的 probe，或是換到另一個 benchmark，
先前留下的經驗仍然能幫助 editor 修改 harness。

最後回到三個動作。

Adapt，是根據目前 task 的執行證據，提出、測試並整合 harness 修改。

Remember，是把可以重用的 component 和有證據支持的修改經驗留下來。

Reuse，是在新 task 裡，讓 editor 選擇相關經驗，再調整成這一題需要的版本。

實驗裡，一次 improvement step 就改善了三個 benchmark、四種配置的 base 表現。Ablation 支持 library、editor 分工和 composition 的作用，
library 的實驗也顯示，先前經驗能幫助之後的修改。

被問到限制時，最需要交代什麼？

Behavioral contrast 提供的是行為證據，不能保證成果正確；執行有隨機性，model 也可能共享偏誤。更多探索需要計算成本，舊經驗能否重用仍要看新 task 的條件。這些都應連回實驗的具體設定回答。
